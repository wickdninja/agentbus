First run Watch Demo README

Watch: see who did what, and what just moved

Two changes for PR B. Each agent keeps one colour wherever it appears, and a claim that changes hands is marked for three seconds. Everything else on the screen is today's watch.

W1Colour means who

Today the second agent and the answer kind are both cyan, the third agent and the question kind are both magenta, and the roster colours only the dot. Switch between Today and PR B on each frame. In PR B an agent's colour belongs to that agent alone: its dot and name in Agents, its claims, and both ends of its messages. Kinds keep their word and emoji and lose their colour, except alert, which stays red. Yellow is the bus: the header, the goal and the change mark.

OrderBlue, magenta, green, cyan, then bright blue, bright magenta, bright green, bright cyan, in roster order, so the first eight agents never share one. A ninth takes one from its name.
Never used for agentsYellow (the bus and what just changed) and red (alerts).
Without colourNames are always written out, so nothing depends on colour. NO_COLOR, a pipe and --json carry no codes at all.

W2A claim changes hands

The worker releases src/auth/ and the lead claims it. Without a mark, one name swaps for another in a list and nobody notices. The mark uses the same bar watch already draws beside a new message, so there is one thing to learn.

0 msFirst paint with the new holder: a yellow bar, the holder's name on yellow, "from worker".
1000 msNext paint: the name goes back to its own colour, in bold. The bar and "from worker" stay.
3000 msThe row is plain again, with its time left back.

The three paints, at 60 columns

At 60 columns "from worker" takes the place of the time left while the mark lasts, and the time comes back with the plain row.

WhenA claim appears with a holder other than the last one watch saw on that resource in the previous 10 seconds. A release and a new claim between two reads count, so do the demo's steps.
How long3 seconds, the same as a new message's mark. Watch repaints once a second, so the 0 and 1000 ms paints are two refreshes. With a longer --interval each paint still shows at least once.
Pausep freezes the whole view, mark included, as it does today. Reduced motion is the same switch.
Never in outputThe mark lives only on watch's live screen. --json, --once, claims, brief, hooks and anything an agent reads never carry it.
What it cannot seeTwo hand-overs inside one second (worker to lead and back) look like no change. The record is in agentbus log.

W3NO_COLOR

With NO_COLOR=1 watch draws no colour codes at all, today and in PR B. The bar and the words "from worker" still mark the row for 3 seconds; the 0 and 1000 ms paints look the same.

W4Not a terminal

Piped, redirected or in CI, watch prints one frame with no colour and exits, as it does today. One frame has no frame before it, so there is no mark. Nothing in this frame changes in PR B.

W5Nobody here yet

Watch already keeps the goal and facts when nobody is on the bus. What changes is the Agents line. Switch between Today and PR B to compare. Today it says to join by hand, which a person who just set up hooks has no reason to do. In PR B it says that sessions join by themselves and names the two real reasons none has: Codex hooks not trusted yet, or a setup step missing.

A fresh bus with no goal keeps today's "no goal yet" line; only the Agents lines change.
