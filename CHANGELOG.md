# Changelog

## Unreleased

### Added

- `agentbus update [DIR ...] [--check] [--dry-run] [--all-buses] [--no-buses] [--no-setup]`: installs the latest GitHub release: it downloads the release wheel and `SHA256SUMS` (size- and time-limited, TLS verified, into a 0700 cache folder), checks the wheel's sha256, and installs that local file with the tool that installed agentbus (`uv tool install --force`, `pipx install --force` or the install's own `pip`), with no source build and no package index. A release without a wheel or checksums, a copy it may not replace (a clone, a fork, an unknown install) or no safe installer gets the command to run (`manual_step`); a wheel that does not match is refused (`download_failed`). Then it upgrades every known bus folder with the new version and runs `setup --refresh`. New error codes: `installer_failed`, `manual_step`, `release_offline`, `rate_limited`, `release_unknown`, `download_failed`, `update_running`. In an agent session (`CLAUDECODE`, a Codex shell, `AGENTBUS_AGENT_SESSION`, or a stream that is not a terminal) it covers only the current bus and says why; `--all-buses` widens it. Bus folders made or upgraded by `init` and `upgrade` are remembered for it (`~/Library/Application Support/agentbus/buses.json` on macOS, `$XDG_STATE_HOME/agentbus/` elsewhere). From the first release that publishes a wheel the README's install lines are that wheel's URL; the `git+` form stays documented as the from-source route. See [Upgrade agentbus](docs/how-to/upgrade.md) and [SECURITY.md](SECURITY.md).
- `agentbus setup claude|codex --refresh`: brings up to date what setup installed (the skill, the `AGENTS.md` block, the hooks tagged `agentbus:managed`), adds nothing, and keeps anything you edited, named as `kept (edited). To replace it: agentbus setup claude`; exits 0 when everything is current. `agentbus update` runs it.
- `agentbus doctor` shows the latest release the daily check cached, and how old that answer is, on its `tool` row (a warning with the fix `agentbus update` when it is newer than yours). It makes no network request.
- A release notice, at most once a day: a command run at a terminal on a tool-installed agentbus prints `agentbus: a new release is available: 0.2.0 -> 0.3.0. Run: agentbus update` on stderr after a detached background check of GitHub Releases. Never in CI, with `--json`, in an agent session, from a project copy, a clone or a fork; off with `AGENTBUS_NO_UPDATE_CHECK=1`, `DO_NOT_TRACK=1` or `NO_UPDATE_NOTIFIER=1`. What it sends is in [SECURITY.md](SECURITY.md).
- `agentbus schema [COMMAND]` prints the machine contract: `--json` gives every command's arguments, result shape, error codes, retry rule and exit codes, plus the shared objects and environment variables; without `--json` it prints a one-screen table. Each subcommand's `--help` now ends with its JSON result and retry line.
- Every `--json` error carries `retryable` (boolean). New error codes: `name_active` (a join refused because the name is in use; it was `bad_input`), `bus_unavailable`, `ack_failed` and `output_failed`. Every refusal now has a specific code; none reports `internal`.
- `status --json` and `watch --json` carry `omitted`: the number of rows each section left out (`agents`, `context`, `claims`, `messages`), `0` when complete.
- `join --json` carries `agentbus` (the running copy's version) and `contract` (the JSON contract version, `1`).
- `release RESOURCE --if-held` succeeds, releasing nothing, when you do not hold the claim, for cleanup scripts.
- `--before NEXT` on `read`, `log show` and `ctx history`, and `--after NEXT` on `inbox --peek`, continue a listing from the `next` cursor of the previous page.
- `scripts/gen_reference.py` writes the JSON, error, exit-code, retry and environment tables of `docs/reference.md` from the same registry (`--check` fails when they are stale).
- Bus schema versions: `PRAGMA user_version` holds the bus's schema version (1, the v0.1.0 shape). A new bus is stamped 1; a v0.1.0 bus is adopted by the stamp alone, with no other write.
- `schema_older` and `schema_newer` errors: an older copy meeting a newer bus refuses and writes nothing, naming the fix.
- Migrations with a verified backup: a newer agentbus opening an older bus copies `bus.db` to `.agentbus/backups/bus-v<old>-<UTC time>.db` (0600, checked, newest 5 kept), then migrates, verifies and stamps it in one transaction that a failed check rolls back. `backup_failed` when the copy cannot be made; the bus is then unchanged. The bus must pass `quick_check` and the copy must match it byte for byte; a migration gets 9 s so agents waiting on the bus always get it. When `upgrade` replaced the copy, the old copy is kept beside the backup. Restoring both is documented in `docs/how-to/upgrade.md`.
- `agentbus upgrade --all DIR [--depth N] [--dry-run] [--json]`: upgrades the copy and the database of every bus folder under DIR, one line per bus (upgraded, current, skipped when the copy is newer, failed), and exits 1 when any failed (with `--json`, the `items_failed` error on stderr lists the failed rows). `upgrade DIR` also migrates the bus and reports the schema change and backup (`schema_old`, `schema_new` and `backup` under `--json`).
- A Ctrl-C once `upgrade` has migrated a bus is the `interrupted` error with `committed: true`, naming the migration (`schema N -> M`), its backup and the command that finishes the job (`directory`, `backup`, `migrations`, `rerun` under `--json`). `committed` is also true once `init`, `upgrade` or `setup` has written a file (a copy, `VERSION`, the exclude rule, a config file or its backup); an interrupted error then names those files (`changed`).
- Stale-copy notice: `join`, `status` and `buses` from the installed tool say on stderr when the bus folder's copy is an older release, and name `agentbus upgrade DIR` for that folder. Never with `--json`, never from the bus's own copy; `AGENTBUS_NO_UPDATE_NOTICE=1` turns it off. `buses` shows each copy's version; `buses --json` rows gain `copy_version` and `stale`.
- A command stopped by the 8 s hold limit while a write was being saved can no longer say the write was not saved: its outcome is not known. The error says the write may or may not have been saved, carries `committed: true` (a repeat needs the write's `--request-id`) and, under `--json`, `outcome_unknown: true`. A stop at any other moment is unchanged. The hold is 8 s unless the process is blocked on a stalled disk, where it lasts as long as the stall.
- `bus_unavailable` also covers a bus file agentbus refuses to touch (a link, a hard link, another owner, the wrong type), named in the message.
- New error codes: `copy_newer` (a folder's copy is newer than the tool; `upgrade` and `init` never downgrade it), `schema_corrupt` (a `user_version` no release writes) and `items_failed` (some buses of `upgrade --all` or files of `setup` failed; stdout holds the whole result).
- One entry point, `cli()`: the installed command (`agentbus = "agentbus:cli"`) and `bin/agentbus` both run it, so an unexpected error under `--json` is a JSON `internal` error either way.
- Read-only opens: `watch`, `upgrade --dry-run`, and `who`, `status` and `read` run without a name on a current bus change no data or schema: they never create, stamp or migrate a bus, and run with `query_only`. They open the bus as every command does, so they may finish SQLite's recovery of a crashed writer's journal (folding its committed -wal frames into bus.db). `upgrade --dry-run` applies no upgrade and writes no copy or backup. On a folder with no bus.db yet `who`, `status` and `read` create it, and on an older bus they migrate it after a backup, like every other command. On a bus `watch` cannot read, the live view says so and names the fix instead of drawing empty sections.
- `agentbus setup claude|codex` installs the skill for Claude Code or the agentbus block in Codex's `AGENTS.md`, with `--scope`, `--dry-run`, `--uninstall` and `--json`. A refused or failed file exits 1 with the `items_failed` error; a change that saved a backup names it (`backup`). See [Set up your agents](docs/how-to/setup.md).
- Claude Code plugin: this repo is the plugin and its own marketplace (`/plugin marketplace add wickdninja/agentbus`, then `/plugin install agentbus@agentbus`). Five quiet hooks join the folder's bus when a session starts and say the session's exact name and how many agents and messages are waiting, say how many are unread when a prompt is sent, note a claim held by another name (or, with another agent live, none) before an edit, remind you at the end of a turn about claims still held without a handoff or done (once for each set of claims), and leave when the session ends. They add counts and fixed text only, run the plugin's own launcher, which keeps the compiled program in a private per-user cache so a hook does not compile the whole program each time (never a copy in the project), name the installed `agentbus` command, never exit non-zero, never create a bus, never run git, ignore a `.agentbus` that git's index lists, and are silent when there is no bus or it is busy. A bus of another version, or the plugin and `setup` both registering hooks, gets one visible notice per session. A `/clear`, fork or compaction keeps the process's name. See [Use agentbus in Claude Code](docs/how-to/claude-code.md).
- `agentbus setup claude` also registers those five hooks in `settings.json` (user or `--scope project`), each tagged `# agentbus:managed`, with the absolute interpreter and script of the installed tool; when the plugin is installed (asked of `claude plugin list --json`, else read from Claude Code's plugin files) it adds only the skill. `setup claude` now ends `Start a new Claude Code session to load them.`
- `agentbus hook DIALECT EVENT` (hidden): what the hooks run. `AGENTBUS_HOOKS=off` turns every hook off. The skill gains one paragraph about hooks.
- `agentbus skill` prints the bundled skill; `agentbus skill --agents-md` prints the `AGENTS.md` block. Both work without a bus.
- `agentbus doctor [--scope user|project|all] [--json]` checks the installed tool, this folder's bus (opened read-only, found the way every command finds it), the bus folder's copy (version and contents), the Claude Code skill and the Codex `AGENTS.md` block, and prints for each problem a command that fixes it (`fix`) or, where no command can, a sentence (`hint`). It changes no row, table or file and fixes nothing; the read-only open may create an empty `bus.db-wal` or let SQLite finish recovering a crashed writer's journal, as `watch` does. The only program it starts is `git`, for the lookups every command makes. It makes no network call. Exit 0 unless a check failed, then 1 (`items_failed`, with the full result on stdout). See [Check your install](docs/how-to/doctor.md) and [How versions fit together](docs/explanation/versions.md); `tests/test_version_policy.sh` pins how the tool, copy, schema and skill behave for every combination of versions.

- `agentbus watch` is a view to keep open: `Tab` and `j`/`k` move through every section, `Enter` opens any row (a message's whole body, its thread and its reply command; an agent, a claim or a fact with its history), `/` filters by sender, recipient, kind, topic or words, `p` pauses the whole view, `y` copies an id or a reply command (OSC 52), and `?` lists every key. The header counts open alerts and questions; agents show their unread messages and what they hold. It works at 40 columns, without colour or emoji, in ASCII (`AGENTBUS_ASCII=1`, `TERM=linux`) and prints one frame under `TERM=dumb`. A busy bus keeps the last frame; a refused bus names the fix and the view comes back as it was. It restores the terminal after `q`, Ctrl-C, SIGTERM and SIGHUP (exit 129), and says `restart for X.Y.Z` after its bus copy is upgraded. See [Watch your agents](docs/how-to/watch.md).
- `watch --json` messages carry `topic`, and the snapshot carries `unread` (messages waiting per listed agent, read from the cursors without moving them).

- `init DIR` creates a folder that does not exist, with its parents (`mkdir -p`), and says so. A path whose nearest existing parent is not a writable directory, or that is a file, is `bad_input`, with nothing created.

- `post` to a name that has not joined still delivers, and now returns `warnings: [{"code": "recipient_not_on_roster", "name": ..., "did_you_mean": [...]}]` (always an array, empty when fine). In text the same warning is one line on stderr with the closest roster names. Warnings are registered in `schema --json` (`warnings`, `Warning`).
- `join --request-id TOKEN` retries safely: the same name, flags and token return the first result with `duplicate: true` instead of `name_active`, and write nothing. The same token with different flags is `request_id_reused`.
- `--request-id` on every write (`join`, `leave`, `claim`, `release`, `ctx set`, `goal`, beside `post`): one rule, a repeat never repeats the effect. Commands that are already safe to repeat accept it and do nothing different. `log add` has no token yet.
- `request_id_reused` carries `original_id` and its message names the original and the way out (`Original: #5. Reuse the same body or pick a new --request-id.`). `name_active` carries `suggested_name` and the message offers it (`try alpha-2`).
- `leave --json` carries `was_joined`; leaving a name that never joined (or already left) says so on stderr.
- `join --takeover` keeps the tool, model and role it is not told again.
- `ctx set` text shows what changed: `set mode: fast -> slow`.
- `agentbus brief` is one call that tells an agent that has just joined what is going on, in under 400 tokens: the goal, who is here and what each holds and why, open questions (kind `question`, to you or everyone, no answer replying to them, directly or through a chain of replies), your unread handoffs and alerts, facts changed since your last inbox read, and a `next:` command. It only reads and never marks anything read. `--limit N` bounds each section; `--json` is a typed object (`BriefGoal`, `BriefAgent`, `BriefMessage`, `BriefFact`) with `omitted` counts. The skill now starts with `join`, then `brief`, one call fewer than `join`, `status`, `inbox`.
- `agentbus demo` is a 30-second hands-off tour for a person: two scripted agents on a temporary bus (join, goal, a task, a claim, a refused conflicting claim, a handoff, `brief`, a release), each command printed as it runs, then an offer to open `watch` (`--watch` opens it directly, `--no-pause` skips the pauses). It never touches the bus of the folder it runs in and removes its directory on success, error, Ctrl-C and SIGTERM. `--json` runs the tour silently and reports each step.

### Changed (breaking, contract version 1)

- GitHub Releases is the only release channel. The release workflow no longer has a PyPI job, `verify_published.sh` has no `--pypi`, and `scripts/release_check.py` refuses a final tag below the highest existing final tag (so GitHub's latest release is also the highest final version) and checks that `DIST_NAME` equals the project name in `pyproject.toml`.
- Every write needs a name on the roster: `post`, `ctx set`, `goal` and `log add` under a name that has not joined (or has left) fail with `not_on_roster`, as `claim` always did. Before: they succeeded. Run `agentbus --as NAME join` first.
- `post --to X --to Y` is `bad_input`. Before: the last `--to` won and the message went to one name without a word about the other. Post once per name, or leave `--to` off for everyone.
- `goal` is a reserved fact key: `ctx set goal ...` is `bad_input` (`goal is reserved; use: agentbus goal TEXT`), and `status` and `ctx get` no longer list it among the facts. `ctx get goal` and `ctx history goal` still read it.
- `join` accepts only names the hooks can print, `[A-Za-z0-9._-]{1,40}`; others are `bad_input` naming the rule. Names already on a bus keep working everywhere except `join`.
- A claim renewal with the same purpose writes no log row; the first claim and a changed purpose still do.
- `--limit` below `-1` is a usage error on `who`, `claims`, `inbox`, `ctx` and `log` (`-1` still means all).
- `post --json` results carry `warnings`; `leave --json` results carry `was_joined`.

- `watch`: `Esc` no longer quits (it goes back, or clears a filter) and `q` quits only from the main view; in a detail or help `q` goes back one level. Before: `q`, `Q` and `Esc` quit from anywhere. Use `q` from the main view or Ctrl-C.
- Listings return an envelope under `--json`: `who`, `inbox`, `read`, `claims`, `ctx get` (without a key), `ctx history`, `log show` and `buses`. Before: a bare array, `[{"name": "a", ...}]`, with truncation announced only as prose on stderr. After: `{"v": 1, "items": [{"name": "a", ...}], "has_more": false, "next": null}`. `items` is the old array with the same rows and order; `has_more` is `true` when `--limit` left rows out (so `inbox --limit 0 --json` is no longer an unmarked `[]` while messages wait); `next` is a cursor for `ctx history`, `read`, `log show` and `inbox --peek`, used with the new `--before NEXT` (and `--after NEXT` for `inbox --peek`). The `N more not shown` line on stderr is gone. Scripts that read a bare array must read `.items`; a bare `[...]` from a listing means a 0.1.x copy.
- One exit-code mapping, the same with and without `--json`: `0` success; `1` the command ran and refused (a claim conflict, a missing message, a name in use); `2` usage (bad arguments, unknown commands, a missing identity, invalid values); `3` the bus is unavailable or unsafe (no bus, busy, a refused schema, an unsafe folder); `4` internal error. Before: argparse errors exited 2 without `--json` and 1 with it, unknown commands exited 1, no bus and busy exited 1, and a crash exited 1 with a traceback. Scripts that test `$? -eq 1` for bad input or a missing bus must test 2 or 3.
- Joining a name that was active in the last 30 minutes fails with `name_active` (exit 1, with `agent` and `last_seen_min`). Before: `bad_input`.
- `ctx set` and `goal` report `unchanged`: setting the value already stored writes no history row (and no log row for `goal`) and returns `"unchanged": true` with the stored `updated_by`, `updated_at` (`set_by`, `set_at`). Before: every call appended a history row. Every `ctx set` and `goal` result now carries the `unchanged` key.
- `inbox` failing to mark messages read (`ack_failed`) exits 3, with the complete messages on stdout; before, it exited 1 and the error code was `internal`. Its message no longer says "above".
- `status --json` no longer prints `N more agents not shown (use --limit)` notices on stderr; its `omitted` object carries the counts.
- Every error carries `committed` (the command's change was saved before the failure; `retryable` is false once it saved database rows, unless the command had `--request-id`; `init`, `upgrade`'s copy and `setup` change only files and stay retryable), Ctrl-C is the `interrupted` error (exit 130 in both modes, JSON on stderr under `--json`), and option abbreviations such as `--js` are usage errors (exit 2) instead of being guessed. A stdout that cannot encode the text is `output_failed` (exit 1); before it was reported as bad input (exit 2).
- `leave` and `release --all` write no log row when there was nothing to leave or release, so repeating them is clean.
- The skill moved from `skill/SKILL.md` to `skills/agentbus/SKILL.md` and now ends with `<!-- agentbus:managed -->`. `skill/SKILL.md` stays as a link to it, so the old README line (`ln -s "$PWD/skill" ~/.claude/skills/agentbus`) keeps working from a clone; `agentbus setup claude` replaces such a link with a real folder.
- README install lines pin a release tag.

### Fixed

- `examples/two-agent-handoff.sh` resolves a relative `AGENTBUS` before it changes directory, so `AGENTBUS="python3 bin/agentbus" bash examples/two-agent-handoff.sh` from a clone works.
- Agent names (`--as`, `AGENTBUS_AGENT`), `post --to` and `--topic`, `read --topic`, `ctx` keys and claim resources refuse control characters and bidirectional overrides with `bad_input` (exit 2); the message and `error.field` name the field and the character is shown as `U+XXXX`. Rows an older bus already holds are still read and shown escaped.
- Deleting claims no longer rewrites the freed pages. SQLite as Debian and Ubuntu build it zeroes every page a delete frees, so `release --all` or `leave` over 500 planted 1 MB claim names wrote about 600 MB with the bus held and could outlive the hold watchdog, making the next agent's command wait. agentbus now sets `secure_delete=FAST`: deleted cells are still zeroed on the pages the delete writes, with no extra I/O.

### Tests

- Workflow tests replay whole multi-agent sessions (handoff, crash recovery, nested buses, first run, upgrade, mixed versions, setup, migration) through the installed command, mutation checks (`bash tests/test_mutations.sh`) show the tests notice broken behaviour, and `scripts/agent-eval.sh` measures whether Claude Code and Codex agents complete the protocol ([docs/evals/README.md](docs/evals/README.md)).
- `tests/run_all.sh` caps every file on every machine (its own helper, `tests/run_capped.py`, kills the file's whole process group and fails it with rc 124); before, the cap needed `timeout` or `gtimeout` and was off on macOS runners.

## 0.1.0 - 2026-11-01

Initial release: a workspace bus in any directory, shared by its repos and linked worktrees. Buses nest; --up selects an outer bus and buses lists the chain. AGENTBUS_DB assigns an explicit bus to sandboxed lanes.

Per-agent inboxes, shared facts and history, advisory expiring claims, an activity log, JSON output, a live watch view, a shared goal (`goal`, shown by join, status and watch), emoji in watch on a terminal (`AGENTBUS_NO_EMOJI=1` turns them off), and an agent coordination skill. Init installs a local copy; path claims are relative to the bus directory.

Supports macOS and Linux, Python 3.9+, and Git 2.31+. One file, standard library only.
