# Claude Code hooks: threat note

What the hooks protect, from what, and what they leave open. The hooks run on every session, so they are held to
"a repository cannot make them do harm".

| Threat | Control | Test |
| --- | --- | --- |
| A cloned repo ships `.agentbus/bin/agentbus` and the hook runs it | Hooks run the plugin's own file or the tool `setup` recorded; nothing is searched for | `test_hooks_claude.sh` TEST 1 |
| The hook tells the model to run that repo copy | Hook text names the installed command `agentbus`; a copy only when the hook itself runs from it | TEST 25 |
| A cloned repo commits a whole bus (goal, messages, a tool) | A `.agentbus` that git tracks is refused; the hook reads git's index itself (v2, v3, v4, split, sparse, with or without a checksum; submodule and linked-worktree layouts) and stays silent when it cannot. Tracked is decided by file identity, not by name: index entries are picked loosely (Unicode NFC and case folding) and each is looked up on disk, because case- and normalization-insensitive file systems resolve other spellings (`.agentbu` plus a long s, a differently cased parent folder) to the same folder; HFS+ also ignores some characters in names (U+200C to 200F, U+202A to 202E, U+206A to 206F, U+FEFF; the set git skips when it looks for a disguised `.git`), so those are dropped before folding, and a bus folder that is a link or whose name on disk is not exactly `.agentbus` is foreign. There is one path: the index is read once, hashed once, and its paths walked (versions 2, 3 and 4, split and sparse); no search of the raw bytes stands in for it. The checksum size is the one whose checksum matches and whose layout parses exactly (a zero trailer from index.skipHash fits either size), and a remembered answer carries a scan version. The candidate list is remembered while the index file's identity (device, inode, size, modification time) is unchanged; SessionEnd skips the check only for the very bus.db (device, inode and, where the system records it, creation time, looked at without following a link; a hard link to it is stopped by the link-count check) its own SessionStart joined, so a planted link or a recreated file gets the full check; a session whose working directory moved to another project gets the full check there. An exclude rule never counts, because every command writes it. A hook never creates a bus | TEST 23, TEST 24 |
| A repository's config names a program git runs (`core.fsmonitor`) | A hook never runs git: it finds the repository and reads the index from the file system | TEST 24 |
| A peer writes instructions into a goal, message, purpose, name or path | Hook output is fixed text, counts and kind names only; nothing peer-written is printed | TEST 7, TEST 99 |
| A hook blocks or slows a session | Always exit 0 (`\|\| true`, a catch-all, `os._exit(0)`); no decisions; 0.3 s busy wait, 1 s hold, 3 s whole-hook limit (1.2 s for SessionEnd) | TEST 2, TEST 3 |
| A hook takes over or releases another live session's name | A foreign name is never taken over or left; unsafe `AGENTBUS_AGENT` values are ignored | TEST 15, TEST 19 |
| `agentbus doctor` runs a command from a hostile `settings.json`, or a planted `claude` | `ClaudeHooksPiece.check` reads text and looks at the file; it starts nothing, not even `claude` (it uses the plugin files) | `test_setup.sh` (check, claude sections) |
| `agentbus setup` starts a `claude` a project planted (`node_modules/.bin/claude`) | Setup starts `claude plugin list --json` only through an executable found on an absolute `PATH` entry (or `AGENTBUS_CLAUDE_BIN`) whose real path is not inside the working directory, any ancestor of it below the home folder (a project root need not be a git repository), every work tree enclosing it, a bus folder or a folder named .agentbus (compared by file identity and by case-folded name), and not tracked in the index of the work tree that holds it (the file, its real path, or any symlink on the way, a directory link included; an index that cannot be read counts as tracked; ignored or untracked files, as in Homebrew's Caskroom or node_modules, are fine), not writable by group or others (the file, the folder it was found in and the folder of its real path), and owned by the user or root. It runs it with the home folder as working directory. Otherwise it reads the plugin files | `test_setup.sh` (claude sections) |
| Writing the user's settings | Refuses invalid or symlinked files, keeps other keys, backs up, tagged entries only | `test_setup.sh` |

## Left open

- The plugin form of the hook command looks up `python3` on `PATH`. A `PATH` that begins with a folder another party can write could run a planted `python3`. The `setup` form records an absolute interpreter and script instead. Claude Code starts plugin hooks through a shell command string, and a plugin cannot know the interpreter's path in advance, so the lookup stays for the plugin.
- An `AGENTBUS_DB` in the environment is a dispatcher's choice and is not second-guessed (no tracked-folder check).
- Any process running as the user can write the bus; names are not credentials (SECURITY.md).
